עדכון אחרון: 15.11.2026 (אחרי שלב 4)

## 2. מבנה הקבצים

המבנה של תבנית הקורס, עם שלושה דברים נוספים: `js/data.js`, התיקייה `images` והקובץ `.gitignore`.

```text
merhav-one-pager/
├── index.html                 ← העמוד עצמו (המבנה והתוכן)
├── css/
│   ├── bootstrap.rtl.min.css  ← Bootstrap (מהתבנית, לא נוגעים)
│   └── style.css              ← העיצוב שלנו: המשתנים ומה ש-Bootstrap לא נותן
├── js/
│   ├── bootstrap.bundle.js    ← Bootstrap (מהתבנית, לא נוגעים)
│   ├── data.js                ← הנתונים: שאלות, תשובות נכונות, משובים
│   └── main.js                ← ההתנהגות: מה קורה בכל לחיצה
├── images/                    ← תמונות ואייקונים
├── docs/                      ← אפיון, תוכן, מערכת עיצוב ומסמך טכני
├── README.md                  ← תיאור קצר של הפרויקט
└── .gitignore                 ← קבצים ש-Git מתעלם מהם (למשל התיקייה .idea)
```

**כללים:**

- קבצי Bootstrap נשארים כמו שהם. כל שינוי עיצובי נכתב ב-`style.css`.
- סדר הטעינה ב-`<head>`: קודם `bootstrap.rtl.min.css`, אחריו הפונטים מ-Google Fonts, ובסוף `style.css`, כדי שהעיצוב שלנו ידרוס את של Bootstrap.
- סדר הסקריפטים: `bootstrap.bundle.js`, אחריו `data.js` ובסוף `main.js`. הקוד ב-`main.js` עטוף ב-`document.addEventListener("DOMContentLoaded", ...)`, כמו בשיעור 1, כדי שירוץ רק אחרי שהעמוד נטען.
- שמות קבצים ותיקיות: באנגלית, באותיות קטנות, בלי רווחים.

## 3. רכיבים ואינטראקציות לפי מקטע

לכל מקטע: איזה רכיב בונים, ומה קורה בכל לחיצה. הנוסחים עצמם נמצאים במסמך התוכן.

### מקטע 0 – Header ופתיח

- **רכיב:** Navbar של Bootstrap, קבוע בראש העמוד לאורך כל הגלילה. ה-header מכיל את התפריט ואת הפתיח, ולכן משתמשים ב-`fixed-top` ולא ב-`sticky-top` (sticky נעצר כשה-header יוצא מהמסך). ה-body מקבל ריווח עליון בגובה התפריט (`--navbar-height`), וקישורים עוצרים מתחתיו (`scroll-padding-top`).
- **תוכן:** לוגו (שומר מקום אפור) · למה לי? · מבט על · הטופס · עכשיו תורכם. כל קישור מוביל ל-id של המקטע.
- **בנייד:** התפריט מתקפל לכפתור ונפתח בלחיצה (Collapse של Bootstrap, כמו התפריט משיעור 3). לחיצה על קישור סוגרת את התפריט.
- **פתיח:** כותרת `h1`, פסקת הפתיח, וההערה על לשון הפנייה בטקסט קטן.

### מקטע 1 – למה לי?

- **רכיב:** טקסט, ואחריו תרשים השרשרת.
- **תרשים השרשרת:** אנכי בכל גדלי המסך, בנוי מ-div-ים ו-Flexbox (בלי CSS Grid ובלי תמונה). מבקש ↓ רכז רכש בחץ ישיר. מאמצע החץ יוצא חץ אופקי דו-כיווני למנהל סניף בצד ימין (כמו "עוזר" בתרשים היררכיה). מרכז הרכש יוצאים שני חצים: "בקשה מלאה נקלטה" (ימין) ו"חסרים פרטים?" (שמאל). מ"חסרים פרטים?" עולה חץ מקווקו ב-`--color-wrong` בצד שמאל של התרשים עד המבקש.
- **נגישות:** הציור כולו `aria-hidden="true"`. לפניו משפט תיאור ב-`visually-hidden` (הנוסח במסמך התוכן), שקורא המסך מקריא.
- **אינטראקציה:** אין. תרשים סטטי.

### מקטע 2 – מבט על

- **רכיב:** טקסט קצר (שליש מהשורה), ולצידו שומר מקום אפור לתמונה או גרפיקה שתיבחר בהמשך, בגובה הטקסט. (עודכן 15.11: במקום הטופס, כדי לא לחזור על הטופס שבמקטע 3.)
- **הטופס:** מוצג לראשונה במקטע 3, בנוי ב-HTML עם שדות נעולים. אותו מבנה משמש את מקטעים 4 ו-5.
- **אינטראקציה:** אין.

### מקטע 3 – מבנה הטופס

- **רכיב:** הטופס, עם שלושה כפתורים ממוספרים (1, 2, 3) בצד ימין של כל חלק. כל חלק בשורה משלו, וההסבר שלו מימין לו.
- **לחיצה על כפתור:** ההסבר של אותו חלק נפתח (Collapse של Bootstrap), בלי Modal. במחשב מימין לחלק, בנייד מתחתיו.
- **פס התקדמות:** אנכי וצר, בין הטופס לקצה השמאלי של המסך, ונשאר במקום בגלילה (sticky). מציג "1 מתוך 3". כפתור שכבר נפתח מקבל סימן ✓.
- **נעילה:** מקטעים 4–6 גלויים ונעולים עד שפותחים את שלושת החלקים (החלטה 15.11). אז כפתור "להמשך" נפתח ומוביל למקטע 4.

### מקטע 4 – בדיקת בקשה

- **רכיב:** הטופס של נועה לוי, מלא חלקית ונעול, ומתחתיו שתי השאלות.
- **בלי רמזים:** השדות החסרים לא מסומנים באדום בעמוד. הלומד צריך למצוא אותם בעצמו (הסימון האדום במסמך התוכן הוא רק לנו).
- **שאלה 4.1:** כפתורי radio (כן / לא) וכפתור "בדיקה".
- **שאלה 4.2:** תיבות סימון (checkbox) וכפתור "בדיקה".
- **לחיצה על "בדיקה":** מופיע משוב (Alert) מתחת לשאלה. במשוב חלקי, התשובות הנכונות שנבחרו מסומנות בירוק. אפשר לשנות ולבדוק שוב.
- **נגישות:** אזור המשוב מסומן `aria-live`, כך שקורא מסך מקריא אותו כשהוא מופיע.

### מקטע 5 – עכשיו תורכם

1. **פתיח:** טקסט וכפתור "התחלה". לחיצה מציגה את התרחיש ואת הטופס.
2. **הטופס:** חלקים א' ו-ב' פתוחים למילוי. תאריך הבקשה מתמלא אוטומטית בתאריך היום. חלק ג' נעול.
3. **"שליחה לאישור מנהל סניף":** מופיעה טעינה קצרה (Spinner של Bootstrap, כ-1.5 שניות), ואז:
    - **חסרים שדות או שדה לא בפורמט הנכון:** מגיע מייל החזרה מהמנהלת. השדות הבעייתיים מסומנים באדום, עם ההודעה מטבלת ההודעות.
    - **חלקים א' ו-ב' מלאים:** מגיע מייל האישור, וחלק ג' נפתח.
4. **המייל:** כרטיס (Card) שנראה כמו מייל, בתוך העמוד מעל חלק ג'. הוא נשאר גלוי, כדי שאפשר יהיה להעתיק ממנו את השם ואת התאריך.
5. **"העברה לרכש":** בודקים את כל השדות מול התשובות הצפויות. כל שדה מסומן בירוק או באדום, ומופיע משוב כללי: נכונה, חלקית או שגויה.
6. **אחרי המשוב:** בחלקית או שגויה, מתקנים ומעבירים שוב. בנכונה, מופיע מקטע 6.

### מקטע 6 – סיימתם את התרגול

- **רכיב:** כרטיס סיום עם המסר הסוגר. מופיע רק אחרי העברה נכונה לרכש.
- **כאן נקבע סיום היחידה** (הנקודה שתתחבר ל-LMS בשלב הבא).

### מקטע 7 – Footer

- **רכיב:** Grid של Bootstrap. במחשב עמודות: לוגו ואודות · מפת אתר · יוצרות וקרדיטים. בנייד אחת מתחת לשנייה.
- **אינטראקציה:** אין.

## 4. מבנה הנתונים (JSON)

הקובץ `js/data.js` מחזיק את כל מה שהקוד צריך כדי לבדוק תשובות ולהציג משוב: מה נכון, איך בודקים, ומה כותבים בכל מצב. הנוסחים עצמם מועתקים מילה במילה ממסמך התוכן. זה אותו רעיון כמו מודל ה-JSON משיעור 2: אובייקט אחד, ולולאה שעוברת עליו.

### המבנה

```javascript
// All checkable data for the unit: answers, rules and feedback texts.
// Texts are copied word for word from content-merhav.md.
const unitData = {
  questions: [
    {
      id: "q1",
      type: "single",            // radio
      correct: ["no"],
      options: [
        { id: "yes", text: "כן." },
        { id: "no", text: "לא." }
      ],
      feedback: { empty: "...", correct: "...", wrong: "..." }
    },
    {
      id: "q2",
      type: "multi",             // checkbox
      correct: ["need", "sku"],
      options: [ /* 6 options */ ],
      feedback: { empty: "...", correct: "...", partial: "...", wrong: "..." }
    }
  ],
  practiceForm: {
    fields: [
      {
        id: "role",
        part: "A",
        accepted: ["מזכיר הסניף", "מזכירת הסניף"],
        messages: { empty: "...", mismatch: "..." }
      }
      // ...one object per field
    ],
    managerEmails: { returned: { subject: "...", body: "..." }, approved: { subject: "...", body: "..." } },
    feedback: { correct: "...", partial: "...", wrong: "..." }
  }
};
```

### השדות בתרגול (מקטע 5) ואיך בודקים כל אחד

| id | שדה | חלק | בדיקת פורמט | מה נחשב תואם |
| --- | --- | --- | --- | --- |
| `fullName` | שם מלא | א' | — | כל ערך שאינו ריק |
| `role` | תפקיד | א' | — | מזכיר הסניף / מזכירת הסניף |
| `branch` | סניף | א' | — | אשדוד (מהרשימה) |
| `requestDate` | תאריך הבקשה | א' | — | ממולא אוטומטית, לא נבדק |
| `need` | הסבר הצורך | א' | לפחות 3 מילים | עובר את בדיקת הפורמט |
| `itemName` | שם הפריט | ב' | — | ארון מתכת דגם R11 |
| `sku` | מק"ט | ב' | ספרות בלבד | 55210 |
| `quantity` | כמות | ב' | מספר שלם גדול מ-0 | 2 |
| `approverName` | שם המאשר | ג' | — | דנה אברהם |
| `approvalDate` | תאריך אישור | ג' | — | התאריך שבמייל (תאריך היום) |

### כללי ההשוואה

- מתעלמים מרווחים מיותרים בהתחלה, בסוף ובין מילים.
- מתעלמים מאותיות גדולות וקטנות באנגלית (r11 = R11).
- שדה ריק או שלא עובר בדיקת פורמט ← מייל החזרה מהמנהלת (בשליחה לאישור). שדה שלא תואם לתרחיש ← נתפס רק בהעברה לרכש.
- ספירה למשוב כללי: כל השדות תואמים = נכונה. חלק = חלקית. אף אחד = שגויה. `fullName` ו-`requestDate` לא נספרים, כי אין להם תשובה נכונה.

## 6. Wireframe וגריד

השרטוט המלא (מחשב ונייד) נמצא ב-FigJam: https://www.figma.com/board/tYxDZIzAHH5TFYV2h8ZRjK. הטקסט כאן מתאר אותו בשביל הקוד.

### כללי גריד

1. **שוליים מקצות המסך בכל גודל:** כל התוכן בתוך `container` (לא `container-fluid`). בנייד מוסיפים ריווח צדדי (`px-4`), כך ששום טקסט לא צמוד לקצה המסך.
2. **שום תוכן לא נוגע בקצה של אזור צבעוני:** כל כרטיס, משוב, כרטיס מייל וקופסה מקבלים ריווח פנימי (`p-3` בנייד, `p-4` מ-992px).
3. **רקע צבעוני לכל רוחב המסך:** הרקע על ה-`section`, עם ריווח אנכי (`py-5`), והתוכן נשאר בתוך ה-`container`.
4. **רווח בין עמודות:** `g-4` בכל `row`.
5. **נקודת השבירה:** עמודה אחת עד 992px, ומ-992px (`lg`) עמודות. אותה נקודה שבה הכותרות גדלות (מערכת העיצוב).
6. **סדר ב-HTML = סדר בנייד:** ב-RTL העמודה הראשונה מופיעה מימין. בכל מקטע הטקסט בא ראשון, והוא גם מופיע מימין במחשב ולמעלה בנייד. לא משתמשים ב-`order-*`. חריגה אחת מכוונת: במקטע 3 כל שורת חלק+הסבר מקבלת `flex-lg-row-reverse`, כדי שבמחשב ההסבר יהיה מימין לחלק ובנייד מתחתיו. סדר הקריאה נשאר חלק ואז הסבר.

### מקטע אחרי מקטע

| מקטע | מחשב (מ-992px) | נייד: הסדר מלמעלה למטה |
| --- | --- | --- |
| Header | לוגו + תפריט בשורה אחת, קבוע בראש העמוד (`fixed-top`) | לוגו + כפתור ☰, התפריט נפתח מתחת |
| 0 פתיח | טקסט `col-lg-6` + תמונה `col-lg-6` | כותרת וטקסט ← תמונה |
| 1 למה לי? | טקסט `col-lg-6` + תרשים מסתעף אנכי `col-lg-6` | טקסט ← תרשים (אותו תרשים אנכי) |
| 2 מבט על | טקסט `col-lg-4` + שומר מקום לגרפיקה `col-lg-8`, בגובה הטקסט | טקסט ← שומר מקום |
| 3 מבנה הטופס | הנחיה ברוחב מלא. מתחתיה, משמאל לימין: פס התקדמות אנכי `col-auto` · החלק בטופס `col-lg-7` · ההסבר שלו `col-lg-5` (שורה לכל חלק). להמשך מתחת לחלק 3 | הנחיה ← חלק 1 ← הסבר 1 ← חלק 2 ← הסבר 2 ← חלק 3 ← הסבר 3 ← להמשך. הפס האנכי משמאל |
| 4 בדיקת בקשה | הנחיה ברוחב מלא. מתחתיה: הטופס של נועה `col-lg-6` + שאלות ומשוב `col-lg-6` | הנחיה ← הטופס של נועה ← שאלה 1 + משוב ← שאלה 2 + משוב |
| 5 עכשיו תורכם (פתיח) | טקסט + התחלה `col-lg-6` + תמונה `col-lg-6` | טקסט ← כפתור התחלה |
| 5 מילוי הטופס | התרחיש `col-lg-4`, נשאר גלוי בגלילה (`sticky-lg-top` מתחת לתפריט) + הטופס, כרטיס המייל, חלק ג' והמשוב `col-lg-8` | התרחיש ← חלקים א' ו-ב' ← שליחה לאישור ← כרטיס המייל ← חלק ג' ← העברה לרכש ← משוב |
| 6 סיימתם | טקסט `col-lg-6` + תמונה `col-lg-6` | טקסט ← תמונה |
| 7 Footer | שלוש עמודות `col-lg-4`: לוגו ואודות · מפת אתר · יוצרות וקרדיטים | אותו סדר, אחד מתחת לשני |

**כרטיס המייל במקטע 5:** יושב בעמודה הראשית, מעל חלק ג', גם במחשב וגם בנייד. בעמודה הצדדית נשאר רק התרחיש. (הוחלט 15.11, כדי שכלל 6 יתקיים בלי order-* ובלי CSS Grid.)
